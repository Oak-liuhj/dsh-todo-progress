# DSH 升级适配与维护

目标是让后续每次 DSH 升级都有检查、回退和发布依据。未发布宿主可能修改插件接口，无法事先保证所有未来版本；检查通过也不会自动修改兼容声明或发布插件。

## 当前证据

| 宿主 | 验证级别 | 结论 |
| --- | --- | --- |
| `0.2.1-rc.5` | 已发布 1.2.1 的 Web / 桌面实机验收；本次代码的回归测试与官方声明结构检查 | 保留 `engines.dsh` / `dsh.verifiedDsh` 原声明；新代码尚待发布前实机复验 |
| `0.2.2-rc.1` | 2026-11-11 获取 npm 官方包并核对声明结构 | 所检查的接口仍存在；尚未完成该宿主的 Web / 桌面实机验收，不标记为运行时已验证 |

本次工作在未发布源码上进行，npm 的 `1.2.1` 不会随仓库修改自动更新。

## 升级时如何保持可用

- 核心任务正文和标题优先注册。右上角入口、布局、旧输入区面板、会话导航分别处理注册失败，包括宿主稍后才声明插槽的情况。
- 一个可选集成失败时，在开发者控制台输出一次带能力名称的提示，继续注册其他部分。核心插槽或任务投影被移除时仍需要修改适配器；无法凭空恢复宿主已删除的功能。
- 入口保留宿主原组件、store、inject 和 locale；卸载注销自己的注册与订阅，不修改宿主源码。
- 新版使用 `panel.isFloating`；旧版使用已确认的 `data-dockkit-pane` / `data-dockkit-float` 标记。未知展示方式、全屏、浮动面板均保留宿主宽度。宽度恢复失败不再中断其他清理。
- 适配代码集中在 `src/client/host/`。缓存键沿用旧值，避免升级丢失偏好；服务端 owner 认证、同源与请求校验保持有效。

可选功能缺失时，可以从宿主右侧栏的任务进度引导入口打开面板；这要求宿主的标签注册和正文插槽仍可用。

## 自动检查

[DSH upgrade compatibility](../.github/workflows/host-compatibility.yml) 在默认分支配置后，每天 UTC 02:17（北京时间 10:17）检查一次，也支持手动运行、主分支提交和 PR。GitHub 调度可能延迟，实际执行与启停状态以 Actions 为准。

检查三组目标：包中 `verifiedDsh`、npm `latest`、npm `next`。每组先运行插件测试和发布格式检查，再生成独立 JSON 报告，报告保留 30 天。CI 失败可通过 GitHub Actions 的通知设置接收提醒；不自动发 Issue、不自动发布或修改兼容范围。

本地运行：

```powershell
npm test
npm run check:release
npm run check:host -- --host verified
npm run check:host -- --host latest
npm run check:host -- --host next
# 或指定一个已发布的宿主版本
npm run check:host -- --host 0.2.2-rc.1
```

报告默认写入 `.local-validation/host-compatibility/`。可用 `--report <path>` 指定位置。脚本只从 npm 官方源读取元数据和安装包，校验 SHA-512，然后用系统 `tar` 将声明读入内存；不安装或执行宿主脚本，不读取或修改用户 DSH profile、会话和凭据。

检查沿 `dsh → dsh-web-app` 的精确依赖选择客户端包版本，部分服务端包取主包直接依赖。各组件自己的 `latest` 标签可能停留在旧版本，因此不能用于拼装检查环境。主包依赖不再精确固定、包缺失、网络失败或完整性校验失败，均作为检查失败保留原因。

结构检查覆盖任务插槽的种类与作用域、注册与导航方法、任务投影入口、布局字段、owner 认证入口及部分会话服务方法。它使用 TypeScript AST 识别声明，**不执行完整类型检查，也不覆盖参数语义、宿主运行时、DOM 或模型工具行为**。回归测试则对生成的真实 `client.js` 注入接口缺失、抛错与延迟注册等场景；模拟宿主不替代实机。

## 每个新版本的发布流程

1. 对目标 DSH 精确版本运行上述检查，核对报告中的包版本与失败原因。接口变化时只修改对应适配器，并增加能复现问题的回归测试。
2. 使用单独的 `DSH_HOME` 和测试 profile 安装目标宿主及本地插件包；不要直接升级唯一的日常工作环境。保留升级前备份与旧插件安装包。
3. 在 Web 与桌面各自验证：空白会话入口、重复点击复用标签、`todo_write` 更新进度、任务筛选、缓存与导出、完成收起、旧面板开关；切换会话后数据对应正确。
4. 验证侧栏半宽、手动拖动、切换工具后恢复、全屏和浮动窗口；禁用/卸载后原入口恢复，无悬挂订阅或清理异常。
5. 验证新建会话继承工作区；查看者仍无修改权限；配套分卷插件存在和缺失时分别验证。无需为兼容新宿主关闭认证或放宽校验。
6. 保存宿主版本、客户端种类、测试结果及脱敏截图后，再更新 `engines.dsh`、`dsh.verifiedDsh` 和发布检查。保留区间时需明确区间的验证依据；不能仅因接口声明存在就扩大范围。
7. 增加插件版本，重建客户端，更新市场包地址、变更记录并发布新包。npm、GitHub Release、市场目录与索引分别验证，不能把其中一个成功当成全部完成。

维护者需在 Actions 中查看新版本报告并完成实机验收；当前机制负责发现变化，不会自动修复尚未知晓的宿主改动。
