# R2 缺口补齐与本地 Web 验证

版本：`dsh-todo-progress 1.1.0`；联动适配：`@deepseek-ai/dsh-session-rollover 1.0.1`。

依据：本机《DSH三条需求_需求规格说明书_v1.2》《DSH插件研究_PRD_v1.1》、研究目录的《设计基线_R2R3_v1.0》与接口契约。保持只读 todos 投影，不增加任务编辑、跨会话聚合或 task_report。

## 已实现与实测

| 需求缺口 | 实现和验证结果 |
|---|---|
| pending 也提示未完成 | 纯 pending 清单显示蓝点，无数字；全完成清单蓝点消失；继承快照使用相同口径 |
| 整面板收起 | 菜单可收起整面板，徽章可展开；不改变任务内容；插件自己的帧存储保留收起状态 |
| 完成后自动收起 | 真实定时器驱动，不依赖其他重渲染；默认 30 分钟，可切换 1 / 60 分钟；新清单重置计时。浏览器以 1 分钟配置静置，约 67.9 秒读取到自动收起徽章，期间没有操作页面或修改时钟 |
| 旧面板兼容开关 | 默认关；使用公开的同 id 插槽 priority 覆盖宿主 todo dock。打开后输入区上方显示完整清单，与右栏共享投影、各自滚动；刷新保留开关；3 项和 24 项清单均实测 |
| 空态菜单 | 没有待办时仍可打开菜单、新建或交接会话 |
| 现在换会话 | 通过经过宿主认证的 R2 操作桥接调用 R3 公共服务，复用分卷事务；真实第 1 / 3 / 4 轮、未达阈值时均成功；工具未收尾仍会拒绝（回归测试） |
| 新建会话 | 新建空白会话，保留工作区，自动打开任务进度，不复制旧待办 |
| 首次继承快照 | 新卷没有实时待办时显示交接快照与明确来源；24 项清单连续手动交接两次后仍完整，父链保留；出现新卷自己的两项清单后立即替换 |
| 上一卷来源回跳 | 「承自 …」按钮可回到旧卷，并显示该卷的任务面板；旧卷封存后手动交接按钮禁用 |
| JSON 复制 / 下载 | 保留只读文本与下载，增加剪贴板复制；复制结果逐项一致；继承快照导出包含来源会话和 inheritedSnapshot 标记 |
| 清空和刷新 | 当前投影曾出现后，即使清空并刷新，也不恢复旧卷快照；中断提示和上一轮快照可跨刷新保留 |
| 布局与滚动 | 稳定布局下 1280×800 / 1024×768 均为 24 行；列表 overflow-y:auto，内容高 876px，可视高分别 571 / 539px；与输入框无交集，面板根 position:static |
| 操作认证 | 未登录调用返回 401；已登录的非法会话 / 非法动作返回 400；单测覆盖非 owner、非法路径及零副作用拒绝 |

## 环境和证据边界

- 正式 Web：`http://127.0.0.1:3080/`，使用安装版 DSH 与用户原有 `C:\Users\Administrator\.dsh\profiles\web`。已安装两个本地源码链接，并验证面板、全部菜单与分卷服务可用；没有向原有会话发送测试消息。
- 完整交互验证：同一个安装版 DSH 的独立 HOME、3081 回环实例，使用本地确定性模型，通过真实模型工具调用执行 `todo_write`。没有脚本直写会话日志、投影或 DOM。
- 安装前的 web profile 配置备份保存在 `.local-validation/web-profile-backup`。桌面 profile 与宿主安装包未修改。
- 测试使用浏览器自动化。Windows computer-use 原生管道不可用，因此没有桌面鼠标实拍。
- 重启测试服务期间旧浏览器连接曾出现一次 `session-maybe` adapter 错误；全新页面与稳定连接复测未复现。最终隔离页面和正式 Web 页面均无 pageerror。
- 自动收起的 30 分钟逻辑用受控时钟回归，真实浏览器静置验证使用可配置的 1 分钟；没有伪称真实等满 30 分钟。
- -9 后独立接续、未完成工具拦截、完整交接消息 16KB 前置校验通过自动化测试；未在真实 Web 人工制造 9 个卷。
- 这次只补充 R2 所需的 R3 联动接口及快照保存，不代表 R3 全部历史缺口已修复。
